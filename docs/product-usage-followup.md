# 从订单继续咨询商品使用方法

修复的场景是：用户刚看完蓝牙耳机订单，接着问“如何使用”，客服却把它当成没有商品对象的新问题，最终返回业务无关提示。

现在的处理顺序：

```text
选择本人订单 → 保存当前订单引用
“如何使用” → 重新核对买家、店铺和订单是否可见
           → 从当前订单商品快照中识别唯一商品名称
           → 本地检索该店当前发布资料和适用的公开使用参考
           → 回答并保留订单引用
“怎么连接手机” / “安卓手机” → 再次核对同一订单并检索对应使用条件
```

回答沿用已有流式传输；资料来源继续保留在结构化审计快照中，用户界面只显示回答。

## 保留和重新读取的内容

服务端仍只保存有限主题指针，不把整段聊天历史当成事实或授权。商品使用咨询沿用 `ORDER` 引用；商品名称每次从当前可见订单读取，使用资料每次从当前店铺发布版本和受控公开目录读取。这个新路径完全在本地处理，不将订单、商品购买关系或商家正文发给模型。

“它呢”“为什么”“再详细一点”等不够明确的续问会先说明可以继续咨询的方向，并保留仍有效的主题。纯澄清不续期，也不直接调用订单或写入工具；用户进一步明确问题后再核对数据。

## 不猜测的情况

- 一笔订单有多种不同商品时，先问哪一件；历史订单缺少商品快照时，要求补充名称和型号。
- 当前店铺没有对应资料时，明确说明缺少使用资料；不能凭订单名称编造充电参数、按键方式或兼容承诺。
- 资料中的平台和型号限制必须保留。普通蓝牙耳机不能套用 AirPods 专属方法，Android 和 Windows 的说明不能当作所有设备通用步骤。
- 订单被买家删除、归属变化或店铺不符时，先按原查单边界拒绝访问，不继续从旧订单提取商品。
- 退款、支付、确认收货、修改和审批仍走原显式业务流程，商品引用不代表提交或批准的同意。

## 历史和有效期

原 30 分钟主题有效期保持不变。刷新或重新登录同一账号、同一店铺时，可以恢复尚有效的主题；明确清空、换主题和人工接待结束等边界不会被向前扫描历史绕过。

已经保存为无主题的旧拒绝回复不会被改写或猜测修复。升级后，用户可点击一次历史订单卡的“查询最新订单”重新建立主题，再继续问使用方法；之后的正常商品续问会保持连贯。过期时也需要重新选择订单或明确商品对象。

实现主要位于 `ConversationContextEngine`、`ProductUsageQuestion` 和 `KnowledgeService.answerProductDetailed`。没有新增数据库表、授权或模型配置。

# 聊天查单与账户金额汇总

顾客明确发送“转人工”“找人工客服”等请求时，优先返回 `HUMAN_SUPPORT` 引导，回复下方显示「联系人工客服」。不调用模型或知识检索，也不把请求误当成订单查询、退款操作。仅在顾客点击按钮后复用现有的人工接待接口、会话归属校验及幂等请求；提示消息本身不创建人工会话。普通的“不用转人工”“取消转人工”等表达不显示该按钮。提示类型随消息保存，刷新后仍可点击；已进入人工接待时隐藏消息中的重复入口。

普通发货追问（如“为什么还不发货”“怎么还没发货”）不是商品名称。存在有效的已选或会话订单时，重新核验当前买家、店铺和订单，读取最新状态；没有可用订单时请买家先选择，不自动挑选最新订单。明确说出另一件商品时，商品定位优先于旧订单引用。

对待发货订单，只说明当前状态以及尚无具体原因；不编造库存、仓库、延迟或承诺时间。普通问候返回帮助，未识别业务问题给出补充信息或人工客服建议，不复述用户原文作为答案。商品、物流、售后和知识查询仍沿用现有授权与工作流。

“最近的消费总金额有多少”默认查询**当前登录买家在全部店铺近30天下单、且当前处于 PAID / SHIPPED / COMPLETED 的订单金额合计**：

- 窗口为 `[查询时刻−30天, 查询时刻)`，按现有 `created_at` UTC 字段筛选。没有独立付款时间记录，不宣称这是近30天发生的支付流水。
- 使用数据库 COUNT / SUM 聚合全部符合条件的本人订单，不只计算第一页；金额使用 BigDecimal。当前数据库约束币种为 CNY。
- CREATED 和 CANCELLED 不计入；买家隐藏订单不会抹去交易，因此仍计入。结果是订单总额，**未扣除退款**，不称为净消费或银行账单。
- 回复附截至时刻（北京时间）和统计口径。历史回复是当时的快照，重新提问才查询当前结果。
- 其他时间范围、指定其他买家或单店统计先澄清，不悄悄套用全店近30天口径。查询失败会报错，不伪造成 0。
- 身份来自认证主体，沿用 ORDER_READ 权限。金额和订单记录不交给模型计算或生成；跨店汇总不会建立某一笔订单的上下文。
- 智能对话记录只允许对应买家读取；商家人工会话使用独立的人工消息表，不接收这份跨店金额记录。

没有修改 Agent 状态、Checkpoint、Budget、模型重试、工具写权限或售后人工审批。无需数据库迁移或新增授权；汇总复用现有订单 SELECT 权限。

# 项目边界与证据

SupportFlow 是可独立运行和演示的 Java／AI 应用学习项目。以下描述当前源码已有的行为，供演示、验收和面试时核对；不把学习数据、模型替身或本机实验表述为线上业务成绩。

本版按 Feature Freeze 验收，停止新增功能与 AI 主架构扩展，保留真实缺陷修复和文档纠错。核验基线、已修复 CI 历史及当前能力状态统一见[能力审计](ai-job-gap-audit.md)；最终冻结结论必须绑定最终 SHA 的全部必需 CI 成功结果。

## 谁负责什么

| 范围 | 已实现的边界 | 不能据此宣称 |
| --- | --- | --- |
| 买家与商家 | 全店订单列表按认证买家过滤，单笔查询再同时限制店铺和订单号；商家须有员工绑定、店铺授权及对应权限 | 全店列表包含其他买家订单，或知道订单号／模型同意即可访问 |
| Java 与模型 | LLM 处理不确定的理解与受限规划，只能建议允许的动作及参数；Java 控制身份、授权、业务规则、额度、执行顺序和真实执行 | 模型授予权限、生成 SQL 查询业务库或批准退款 |
| 回复输出 | 校验和持久化完成后以 SSE 分段传输，前端逐段显示；中断只读取历史核实、不自动重发 | 模型生成阶段首 token 直出，或停止显示能够撤销已完成的处理 |
| 多轮 Agent | Observe → Decide → Validate → Execute → Checkpoint；可切换规则、custom DeepSeek 或 Spring AI 适配，State / Checkpoint / Budget 均在 MySQL | 全部聊天都是自主 Agent，或已实现多 Agent 协作 |
| 售后与退款 | 未支付／已取消订单只返回文字说明，不打开退款表单；明确提交原因后创建申请；收货后 15 天、缺失收货时间转人工核实；客服审批后进入持久化模拟执行 | 仅聊天表达退款就立即扣款／返款，或已接入支付渠道 |
| 重试与恢复 | 现有故障分类下，模型／只读步骤有限重试；检查点、代次和租约限制旧执行提交 | 写入可任意重放，或真实支付端到端 exactly-once |
| 知识回答 | 先确认店铺／发布／版本／可见性；词法 + 本地 BGE、加权 RRF 类融合、阈值／回退与 TopK；持久向量与内容 hash 不替代可见性复核 | 所有回答都是模型生成，缓存命中等于有权访问，或已有独立 Reranker |
| 拒答与话题 | 保守规则提前拦截明确无关问题；受限引用支持订单、知识追问，业务无匹配和系统故障另行处理 | 完备的语义分类器、任意代词理解或长期记忆 |
| 展示与审计 | 用户端只展示回答正文；来源、版本和完整快照保留在响应及会话审计 JSON；历史正文不改写 | 隐藏来源卡片等于删除后台证据，或浏览器不能查看响应元数据 |
| 运行规模 | 模块化单体；可选 Redis 共享登录会话；请求配额、模型并发和熔断仍为每实例状态 | 仅共享登录就已具备全局限流、生产高可用或完整集群能力 |

退款网关只生成 `SIM-` 模拟回执；物流读取本项目的本地业务记录。当前没有真实支付退款、快递公司联网接口、微服务、MQ、WebSocket 或 PDF／OCR。它们不是本版求职展示的必补功能。

退款与审批始终是确定性 Java Workflow + 人工批准；模型没有退款工具。售后知识可以解释申请流程和原因分类，不能决定个人订单资格、期限、状态、金额、审批结果或到账。

发货短追问重新校验当前买家／店铺／订单并查最新状态，不凭历史卡片作答或虚构延迟原因。近 30 天消费汇总通过 SQL `COUNT/SUM` 统计认证买家全部店铺、滚动 30 天创建且当前状态为 `PAID/SHIPPED/COMPLETED` 的 CNY 订单，包含已隐藏订单，未扣退款；这不是按支付时间的净消费账本。“转人工”只生成 `HUMAN_SUPPORT` 提示，点击按钮才创建人工服务。

## DeepSeek 到底接收什么

“只允许公开参考资料外发”是知识筛选入口的限制，不能扩展成“所有模型请求都不含订单信息”。启用 DeepSeek 后，各入口的数据如下。

| 模型入口 | 发送给供应商的数据 | 保留在 Java 的责任 |
| --- | --- | --- |
| `DeepSeekOrderIntentRecognizer` | 本次用户消息；消息本身可能含订单号或用户自己输入的信息 | 严格解析意图，只接受原文中的订单参数，重新校验归属 |
| `DeepSeekToolPlanner` | 本次消息、明确选择的订单号、允许工具的 schema | 限制工具、验证参数、校验身份与订单范围 |
| `DeepSeekAgentDecisionPlanner` | 用户消息、所选订单号、已执行工具的订单号／状态及最多 2000 字符的观察正文；正文可能包含金额和物流记录 | 发送观察前复核权限；模型不能修改已执行事实或越过运行预算 |
| `SpringAiAgentDecisionPlanner` | 与原持久化规划器相同范围的问题、所选订单和裁剪后的订单／物流观察，经 DeepSeekChatModel 和原保护层发送 | 相同 `validateDecision`、只读工具和 MySQL 预算／检查点约束，默认不自动启用 |
| `DeepSeekPublicKnowledgeSelector` | 通过受控公开目录逐字段校验的最多两篇参考资料及本次知识问题 | 商家发布资料不进入该外发入口；只接受允许的来源 ID，回答仍采用本地证据 |
| `SpringAiKnowledgeAdapter` | 仅满足同一受控公开目录与问题检查的最多两篇证据和知识问题 | 商家私有／混合候选不外发；返回 ID 再校验，本地证据保留完整条件 |
| `RealModelEvaluationTool` | 工具内置的合成问题和合成订单／物流观察 | 不启动 Spring，不连接数据库，不加载商家资料，不执行业务工具 |
| `SpringAiLiveEvaluationTool` | 工具内置的 6 个合成任务及合成订单／物流观察 | 仅使用一次性 MySQL 和合成业务工具；不读日常库／商家知识，不执行真实退款或审批 |

截断观察正文只是长度限制，不是脱敏。当前没有通用个人信息识别和脱敏网关；真实商用前必须按实际数据要求决定能否发送这些字段。关闭 DeepSeek 时可以使用本地规则与检索，不需要把业务资料发送给供应商。

API Key 只作为供应商 HTTPS 请求的认证凭据，不放进模型提示词、Git、前端或评测报告。数据库账号、密码和服务端认证主体不作为规划提示词字段；这不表示用户自由输入的消息已经经过自动脱敏。

## 数据保存与可见性

- 订单、售后、商家授权、会话、人工消息、知识发布快照和 Agent 检查点保存在 MySQL，各自沿用权限和状态校验。
- 模型看到一次工具结果，不代表下一轮仍有权限。恢复、继续查询和资料读取都需要当前范围与版本校验。
- 知识草稿不会直接成为买家答案；下线后不能借旧向量或历史引用继续回答。旧会话仍保留当时的证据快照用于审计。
- 买家删除订单是买家侧隐藏标记；原订单及商家记录保留。删除聊天窗口不会重放退款、审批或人工消息。
- 用户端隐藏话题提示不移除服务端上下文。取消选单的重置随下一条成功消息保存，发送前刷新不代表已永久清除。
- 登录会话默认使用单机内存，可显式启用 Redis 共享；有效期、CSRF、退出和账号撤销均保留。聊天历史及 Agent 检查点仍在 MySQL。限流、模型并发和熔断仍按实例计数，不能据此宣称完整集群。详见[Redis 共享登录](redis-session.md)。
- Redis 不承担 Agent State、Checkpoint、Budget、ChatMemory 或 Vector Store。人工服务最后一条成功消息空闲 5 分钟后由服务端关闭，等待中的服务同样适用；评价仅允许该会话买家在关闭后提交一次，消息历史不删除。详见[人工接待](human-support.md)。

## 哪种验证能证明什么

| 证据 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 单元／一次性 MySQL／浏览器测试 | 所列代码契约、权限、事务、恢复和页面流程 | 所有自然语言输入正确、实际供应商始终可用 |
| 真实模型评测 | custom 单次决策契约与 Spring AI durable 多轮合成任务分别验证；固定场景的动作、参数、任务状态及该次延迟、usage | 生产准确率、完整客服知识问答质量、生产延迟基线或真实业务收益 |
| 固定订单读取压测 | 指定提交、机器、限额、数据与并发下的结果 | 全站容量、模型吞吐、线上用户数或受控优化倍数 |
| GitHub CI 与交付包 | 对应 SHA 的检查及可追溯构建结果 | 本地后续修改也已通过，或本机结果等于云端结果 |

已有容量报告基于 `6c6aa65` 的 CI 构建；本轮 UI 与回复规则更新没有重新测量容量，旧结果仍按旧提交引用。真实模型成绩以实际报告为准，不把错误、跳过或未运行记成通过。

归档 Spring AI 成绩为 6/6 任务、14 次调用、10081 token，工具选择／参数／任务成功三项比例为 1.0；这仅限小样本合成集，不能简称“Agent 准确率 100%”。Memory、规则式 Query Rewrite、VectorStore / Document、最终回复 Streaming、Prompt Injection、Rate Limit（尚无跨实例全局配额）、Evaluation、Observability 和 Cost / Token Budget 的局限保留 PARTIAL；独立 Reranker 为 NOT_IMPLEMENTED，MQ / MCP 为 NOT_NEEDED。它们不妨碍以明确边界的当前版本准备面试，也不是继续堆技术的理由。

演示入口见[演示步骤](demo-guide.md)，当前运行机制见[多轮 Agent](agent-loop-budget.md)与[故障处理](agent-resilience.md)，测量范围见[模型评测](real-model-evaluation.md)和[容量说明](deployment-and-capacity.md)。
